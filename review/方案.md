**需求归纳（R1~R7，不改写意图）**：
- R1 开源、直连 Oracle/MySQL 等各类库、AI 参与生成报表、功能丰富
- R2 无核心功能收费墙（DataEase X-Pack 教训）+ 必须导出 Excel
- R3 核心工作流：外部 AI（GLM/ZCode，经院内数据资产平台只读查数，内部称 $sjzc）**以 API 把报表直接写进 BI**；同时 BI 支持人工 GUI 制作报表
- R4 上百万条数据的查询与导出（Excel/CSV）
- R5 角色/权限体系；科室、人员不同层级看同一报表数据不一致（行级权限）
- R6 报表嵌入其他系统（OA/门户/HIS）
- R7（本轮新增）AI 能在用户本地直接进行修改等操作（AI 持有本地执行通道，如 ZCode CLI 本身，不只是出报告）

## 2. 背景与边界

**背景**：山东某三甲耳鼻喉专科医院，信息科 1~2 人；数据资产平台统一接入约 20 个业务系统（HIS/LIS/PACS/EMR/HRP/OA/体检/病理等），库型 Oracle + Vastbase（openGauss 系）+ SQL Server + MySQL，提供受控限量只读 SELECT；全院内网，LLM 本地私有化（OpenAI 兼容，DeepSeek/Qwen）；报表用只读账号连 ODS，不直连生产 HIS。

**边界**：本轮只读审查（不部署、不写代码、不改环境）；实施另行授权。

## 3. 选型方案（送审主体）

**主推：Apache Superset，单一主推，双轨架构。**

- **轨道一（常规报表）**：Superset 看板/报表/权限/Excel 导出/定时邮件；GLM 经 REST API 建数据集→图表→仪表盘，人工可 GUI 精修
- **轨道二（百万行明细）**：不走 BI；GLM 经数据平台只读查询后 Python 流式写 CSV/分 sheet xlsx 至共享目录

**核心事实论断（14 条，依据=官方文档/GitHub，详见参考清单第 4 节表格，此处列要点）**：
1. Apache 2.0，无企业版无付费墙
2. oracledb 驱动直连 Oracle
3. 全套 REST API（OpenAPI）：dataset/chart/dashboard 增删改查 + YAML/ZIP 导入导出，JWT 认证
4. 存在社区 Superset MCP Server
5. 仪表板原生一键导出 xlsx（每图表一工作表）
6. 行数上限无硬编码：ROW_LIMIT（默认 5 万）/SQL_MAX_ROW（默认 10 万）可调至百万级（issue #35139 官方确认）
7. 百万行导出需异步（Celery+结果后端+worker 内存回收）；xlsx 单 sheet 硬上限 1,048,576 行
8. RLS 行级权限开源内置（数据集+角色绑定 SQL 子句，Jinja 动态变量 {{ current_username() }}）
9. RBAC 角色内置（Admin/Alpha/Gamma/Public+自定义）
10. LDAP/AD 域 + OAuth2 SSO，域组自动映射角色（AUTH_ROLES_MAPPING）
11. Guest Token 原生嵌入（/api/v1/security/guest_token/，token 携带 rls_rules，嵌入态按人过滤）
12. 嵌入态可交互+导出 CSV，需新版 @preset-sdk/embedded（旧版导出 bug，issue #21829）
13. Alerts & Reports 定时邮件免费内置（celery beat/worker + chromium 截图 + SMTP）
14. 有简体中文语言包

**已排除/降级候选（详见参考清单第 5 节）**：
- 排除：DataEase（X-Pack 收费墙+开放 API 不完整+用户实际用过否定）、Metabase（Oracle 驱动付费）、Grafana（Oracle 插件与定时 Reporting 均 Enterprise 收费）、Wren AI（无 Oracle connector，issue #710）、JimuReport（核心 jar 非纯开源+免费版限 10 万行+无程序化 API）、AJ-Report（2025 RCE 漏洞+更新放缓）、Datart（2022 后停更）、DataGear（无 AI 无程序化 API）
- 降级可选：SQLBot（定位是 BI 内置 AI 问答，与 R3"外部 AI 建报表"路线不符）
- 试点观察：SuperSonic（腾讯音乐，Apache 2.0，ChatBI+语义层契合医疗指标口径管理，但官方数据源列表无 Oracle、Excel 导出未确认→需实测）
- 备选：DB-GPT（Apache 2.0，Oracle V0.7.1+，框架型无现成报表门户，深度定制用）

**待验证风险（6 条，详见参考清单第 7 节）**：
1. Vastbase 不在 Superset 官方数据源列表，PG 兼容接入未实测
2. "AI 全自动建报表"无广泛公开案例，需端到端试点 1~2 张真实报表
3. 部署组件多（web+celery worker+beat+Redis+结果后端+chromium+元数据库+SMTP），1~2 人运维负担
4. 数据资产平台是"受控限量"通道，Superset 需独立只读凭据直连 ODS，需平台侧确认授权
5. RLS 行级非列级（敏感列需拆数据集变通）
6. 中文包有但配置工程化，学习曲线

## 4. 实施步骤（选型通过后，另行授权执行）

1. 测试机 Docker 部署 Superset（官方 compose）
2. oracledb 驱动 + Oracle 只读账号（ODS）连通；Vastbase 以 PG 兼容实测
3. 建 API 服务账号（JWT）；端到端试点：$sjzc 定口径→SQL→API 建 dataset/chart/dashboard→导出 Excel→RLS 配一条科室规则验证
4. SMTP+celery 定时邮件；AD 域对接（AUTH_ROLES_MAPPING）
5. 嵌入试点（EMBEDDED_SUPERSET + Guest Token + 宿主小接口）
6. 推广科室报表；百万行明细走轨道二
