## 证据终审补注（事实类）

**条目 9（对账/回退工具缺陷）——部分成立**：
- `reconcile_report.py`：`row_key()` 返回的是 `tuple(repr(...))`（字符串元组），第 78 行 `k.encode()` 对元组调用——**属实**，元组无 `.encode()`，产生差异时必报错（`AttributeError: 'tuple' object has no attribute 'encode'`）。该行只有在产生差异时才执行，所以"相等数据"测试不会触发——这正是 Codex 警告的"差异被掩盖"。**裁决：成立，须在计划中列为工具修复项。**
- `rollback_batch.py` `references()`：函数注释已写明"近似：图表-看板引用在 P4-S5 用元数据精确判定；此处保守计数"，第 27 行确实在 dashboard 列表上按 `id == chart_id` 过滤——图表 ID 与看板 ID 命名空间不同，结果恒为 0 或误命中同号看板，且函数只对 kind=="chart" 返回非零，数据集直接返回 0。**裁决：属实（函数按注释本就是保守近似），但计划必须禁止把它当"无引用"证据；回退以批次完整快照为准。**
- `cdp.py` Fetch 拦截分支：**属实**（条目 8 已一致），复用浏览器探针时必须禁用该分支。

**条目 16（823 vs 814 列）——双方口径都对，需以 CSV 实数为准**：
- 实测 `migration/batches/AB迁移/交接包/字段中文待完善清单.csv` = 824 行（含表头）= **823 条数据**。方案 §4A 的"823"与此一致；Kimi 引的"814"来自 v1 改进计划正文的另一算法（含后续新增映射抵扣）。**裁决：以 CSV 实数 823 为现行口径，v1 正文 814 为历史口径；计划须写明"以交接包 CSV 实数为准"**。
