## 2. 执行条款复核发现与处置

| 编号 | 发现 | 修订 |
|---|---|---|
| R01 | P1“9卡齐全才通过”与“个别阻塞不影响其余”有冲突 | 全批P0完成后，P1–P6按每表/兼容批次过门禁，逐项推进 |
| R02 | 日报强限单日、月报强限自然月可能改变原范围查询 | 单日/完整月改为首轮验收顺序；旧实际能力须保留，性能限制单列差异 |
| R03 | “全部源查询走QueryGate”可能误读为自动保护浏览器/API | 明确工具与应用执行链不同，真实chart/data、refresh、筛选候选及导出另验 |
| R04 | QueryGate并发锁是本进程内，row_count仅已抓取数量 | 不宣称全网串行或完整结果；额外一行/同条件计数验证截断 |
| R05 | 简略快照不能覆盖所有列/指标/UUID/RLS/owners/权限关系 | 正式执行补私有完整定义/关系快照，恢复验证用本套隔离临时库 |
| R06 | 部门总览可能混用不同粒度或不同范围报表 | 独立页面/限定筛选作用域；权限不同分受控入口，所有历史挂载审计 |
| R07 | “验收通过再部署”对需要真实API的候选形成循环 | 本地定义→工具试跑→受控管理员草稿→真实链路验收→发布门禁 |
| R08 | Q3无旧基准可交付与晚版“赋权/发布留用户”易混淆 | Q3仅豁免独立基准，技术项继续；人员赋权/发布按最新明确许可，不虚构许可或全局停工 |
| R09 | 次日同步未到会导致执行AI长时间空等或提前PASS | 单列延后检查点及命令，其余技术交付完成后正常收尾 |
| R10 | 聚合前范围、导出能力与撤权缓存步骤不够具体 | 补内层范围、RLS组合/默认拒绝、旧会话/API/导出与缓存验证，不盲清全局缓存 |
| R11 | 旧冻结生成器会覆盖round-9与旧台账 | 明确禁止重跑旧finalize_artifacts.py，后续新run_id/新冻结独立保存 |
| R12 | 同号ID跨图表/数据集/角色可能混淆 | 强调ID带类型：保护角色341与本次图表341是不同对象 |
| R13 | 非本批必需后台问题可能扩大到全栈整改 | beat短uptime只登记待诊断，P0按真实必需依赖判断，不凭Up断言健康或全局停工 |
| R14 | 当前目录PBD还不等于老客户端实际加载版本 | 冻结来源时补启动路径/库加载顺序，同名对象不能按glob首个匹配裁定 |

R03/R04来自本地QueryGate源码与6.1.0实际图表执行源码对照，源端取消仍须应用实测。[本地查询工具](../../migration/tools/lib/query_gate.py)、[官方6.1.0图表API实现](https://github.com/apache/superset/blob/6.1.0/superset/charts/data/api.py)。

R10的看板角色回退与读权限行为继续按官方6.1.0核实。[官方安全说明](https://superset.apache.org/admin-docs/6.1.0/security/)。模板字段与过滤辅助宏核对官方正式版本，非Next。[官方SQL模板说明](https://superset.apache.org/admin-docs/6.1.0/configuration/sql-templating/)。
