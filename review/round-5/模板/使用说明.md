# 执行模板使用说明

> 编制日期：2026-10-06。所有 CSV 仅含表头；空模板不构成已完成取证或已通过验收。

先按 run_id / batch_id / report_key 复制到执行目录，不在模板文件填真实结果。完成批次后冻结证据并记录哈希；活动进度文件可更新，前轮和历史批次不能改写。

## 共同键及记录规则

- `source_key`：正式源唯一标识最少由原库/模块/DataWindow/版本/原资产 SHA 确定，不只用标题。本轮台账初始键 `srd339:<模块>:<数据窗口>:<源序号>` 只是提取记录索引，保留不改；P2 查原版本后，在来源卡和原资产 SHA/语义版本字段补充正式标识及对应关系。
- `report_key`：一个已确认业务功能及其语义版本的稳定键；由菜单/窗口/运行分支形成，不与图表 ID 强绑定。一个功能可引用多个来源，一个来源可服务多个功能，关联用分号或独立关系表。
- `principal_ref`：随机稳定人员代号。真实账号、工号、姓名、密码等只在计划指定私有目录；本工作区禁止填它们。部门、范围和操作使用不含身份信息的规范代码或 `scope_ref`。
- `scope_ref`：权限范围定义的引用，实际范围值及与身份的关系按分区保存。SELF 必须来自已证实的业务人员键，不能猜字段。
- `run_id`、`batch_id`、`case_id`、`change_id`：唯一且可追溯；相同测试重跑新增 attempt，不能覆盖失败证据。
- SHA：UTF-8 文件或规范序列化内容的 SHA-256；比较结果摘要若包含可关联患者信息，用带密钥摘要而不是公开低熵标识的普通散列。
- 空字段表示未取得；`不适用` 需填依据；布尔和状态不能把空写成通过。数量是完整范围的数量，1000 行预览不得记为全量。
- 证据路径只指不含敏感内容的公开摘要。私有证据用不可猜身份的 `private_ref`，不要把实际私有映射或数据库备份复制到 review。

## 各模板用途和必填项

| 模板 | 记录粒度 | 必填与注意事项 |
|---|---|---|
| [报表口径卡](报表口径卡.md) | 每个报表功能/语义版本一份 | 调用关系、时间/状态/范围/版本、计算与独立参考，未确认项显式留空 |
| [功能目录](功能目录.csv) | 每个在用/候选功能及版本 | 旧入口、源引用、在用依据、实现路线；“废弃”必须有证据 |
| [参数映射](参数映射.csv) | 每报表每参数每调用分支 | PB 类型、必选/NULL/ALL 含义、条件位置、目标实现、安全引用和边界用例 |
| [计算映射](计算映射.csv) | 每计算/汇总/格式项 | 原表达式、行/组/全局作用域、Null/精度/舍入、目标公式及独立样例 |
| [权限矩阵](权限矩阵.csv) | 人员代号 × 报表 × 操作 × 范围 × 有效期 | 来源版本、ALLOW/DENY/UNKNOWN、字段范围、继承与拒绝；缺证据不赋权 |
| [人员映射](人员映射.csv) | 每人员代号与身份匹配状态 | 只存无身份信息的匹配方法/状态、在职判定证据引用；真实连接键另存私有区 |
| [对账用例](对账用例.csv) | 每报表/版本/条件场景 | 旧独立参考来源、数据时间、权限范围、参数、完整性与必做标志 |
| [对账结果](对账结果.csv) | 每次用例执行 | 行数、计数/金额/组/逐行/计算差异、截断、参考独立性、缓存策略、结论 |
| [权限测试](权限测试.csv) | 每人员类型/入口/操作/范围组合 | 正反向预期、实际拒绝或最小返回范围，直接 API、导出、缓存和撤权均覆盖 |
| [变更记录](变更记录.csv) | 每对象或授权变更步骤 | 变更前后 SHA、计划 SHA、对象 ID/UUID、API 读回、回退包/回退状态 |
| [阻塞事项](阻塞事项.csv) | 每个具体原因与受影响对象 | 必须指出所缺证据及能继续的其他动作，不写笼统“用户没确认” |

## 执行清单和来源台账

[执行清单](../执行清单.csv) 按专项计划中的 Pn-Sm 初始化。“待执行→执行中→通过/失败/阻塞”均要有时间、证据和下一动作。清单阶段通过不代替每张报表的 G0–G6 门禁。

[源对象执行台账](../源对象执行台账.csv) 原始 339 条由 round-4 来源台账生成。已建对象只表示有 ID，不表示已验收；失败来源只保留原记录，不猜原因。多个图表/数据集 ID 用分号保留，不预先删重复。新增发现来源追加新键，并分别汇总原 339 与新发现来源。

对每条来源填处置类型、在用依据与 report_key；业务功能的进度放功能目录。字典/子报表处置与业务报表验收分开记录，避免重算或漏算。

## 对账与授权结论

`通过` 必须满足必做场景全部通过，计数、金额、分组、逐行、多重集和必要计算没有未解释差异，且旧参考独立、数据范围完整、结果没有截断。只比较空结果或总金额不够。

`权限通过` 必须同时验证功能、操作、字段与数据范围；同一人 A 报表科室甲 / B 报表科室乙的交叉用例必测。基础角色和科室归属不构成有权查看全部报表的证据。

任何改进需要改变旧报表数字口径时，另记业务变更，不写成“一致性通过”；不要修改 HIS 业务数据来消除差异。
