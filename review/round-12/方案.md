# 前端界面分析与优化执行计划——盘点方案（round-12）

## 0. 用户原始需求（逐字引述，2026-10-15 会话）

> 请对当前系统的前端界面进行分析，看看能否进行优化和完善？由什么需要改进的地方吗  尽量直观方便操作，综合各个ai意见生成个 执行计划

意图解读（不改写）：以**当前生产前端**（2026-10-15 大改后）为对象做体验分析，找出仍可优化完善、影响"直观方便操作"的点；综合各审查 AI 意见，产出一份可交给执行 AI 的前端优化执行计划文件。

## 1. 目标

1. 以 2026-10-15 现状为基线（不是旧状态），盘点前端剩余改进项，按用户价值与风险排序。
2. 产出《前端界面优化执行计划》落 `migration/`，自含可执行（对象/做法/验收/回退），综合四方意见定稿。

## 2. 边界

- 本轮只读审查+计划编制，不改生产。
- 计划不得授权：发布/赋权、SQL/口径变更、删业务说明、全局样式殃及病案保护页、superset init、动兼容层无复现证据时。
- 遵守 AGENTS.md 2026-10-15 用户交互约定（起止范围默认、日历点选、秒精度、按钮"查询"、紧凑单行 40px 说明区）——这些是**已定案约定**，不是待议项。

## 3. 当前前端基线（证据：20261014-NAVCLEAN/UIFIX、20261015-DATEUI/RANGEUI/2030-SYSFINISH 各"结果说明/完成报告"）

已做（不要重复规划）：
- 目录重构 34→8 分类→27 查询页；顶部入口改"报表目录"；目录卡片可点击。
- flatpickr 4.6.13 本地化日历：月/单日/区间/时刻四模式+快捷项；默认起止范围；×恢复默认。
- 按钮统一"查询"；说明区统一 40px 单行、导航/说明并排；月报单张 HTML 宽表（门诊左/住院右 24 列）+整表 CSV。
- 8 个旧筛选 ID 规范化可应用；手术量分支下拉（数据集 353 固定选项）；36 看板布局修复；图表区 640px；字号 14px。
- 1366×768 与 1920×1080 验收；Chromium 87 全过（真实请求无拦截）。
- 自定义层：`/custom/report-ui.js`（nginx 带版本注入）、`/custom/vendor/flatpickr`、品牌 brand.js、中文 messages、Chrome80-88 兼容包。

已知遗留/线索（拟议池，待审查方挑战）：
- A 交互残项：宽表横向滚动无冻结列（科别列滚出视口）；合计行是数据行不是置底；空数据/错误提示文案与样式未统一中文；筛选标签未全中文；附表（护理日报 24 项附区、床位配置）与主表同页的折叠/分组呈现；多行表头（床位矩阵"率(%)""(日)"单位列头）仍是平铺后缀。
- B 导航与查找：无"搜索报表"能力（27 页靠目录逐级点）；无最近使用/常用置顶；面包屑仅分类返回。
- C 一致性：导出按钮与文件名中文化；各页标题/说明排版风格；错误页 404/401 中文引导（员工打不开时体验）。
- D 现代浏览器水合异常：**口径冲突待裁决**——UIFIX 称"现代 Chrome 复现有内容 DOM，不能定性水合异常"；SYSFINISH 称"经未改页 40/36 对照确证既有水合问题"。院内基准 Chromium 87 不受影响，但新电脑受影响；无复现禁改兼容层。
- E 打印版式：从未对照老系统（方向/重复表头/页边/长表续页）；CSV 已好，打印是缺口。
- F 可维护性：report-ui.js 全局注入层升级回归风险（Superset 升级时）；与 Chrome80-88 兼容包叠加顺序；flatpickr/兼容包/品牌脚本版本台账。
- G 性能感知：重型月报首屏加载态（骨架/进度提示）；筛选应用后无 loading 反馈。
- H 数据展示规范：数值右对齐/千分位/负数红字/率值固定两位——当前 DataTable 默认样式。

## 4. 拟议计划结构（草案，供审查）

分三档：本批可做（纯前端/custom 层、不碰 SQL 与权限、Chromium87+现代双浏览器可验）→ 需取证先行（D 水合复现、E 打印对照老系统取证）→ 不做/留用户（发布、权限、口径、Superset 版本升级）。每项含：对象 ID/页面、做法、验收（两档分辨率+双浏览器+真实请求）、回退（自定义层文件级）。
