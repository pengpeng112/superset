## 1. 目标与边界

**目标**：把 v2 已定案的选型（Apache Superset 6.1.x 主推 + 双轨架构）落成可由另一 AI 逐项执行的部署与安装长任务计划，覆盖：本地开发环境 → 离线介质制备 → 服务器生产部署 → 业务数据源接入 → HIS 用户体系集成。

**边界（本方案不做）**：
- 不做中式复杂报表补丁选型（v2 风险 10 三选一决策留试点期，见第 12 节）；
- 不做轨道二"科室自助明细查询入口"的界面开发（属应用开发任务，非部署安装；其依赖的异步导出基础设施在本方案 P3 内就位）；
- 不执行任何部署动作本身——本文件是计划与核查结果，执行由用户指定的另一 AI 按计划进行；
- 本轮起草阶段不执行 SQL（含只读查询）与服务器写操作（见第 3 节核查说明）。

## 4. 关键决策与依据（D1~D6）

**D1 部署形态：自写生产版 Docker Compose（非官方测试 compose）**
依据 v2 风险 3：官方 docker-compose 仅测试用；生产需 web + celery worker + celery beat + Redis + PG/MySQL 元数据库 + Playwright 无头 Chromium（定时报告）+ 反向代理 + 备份。服务器预计为 Linux（root 账号），Docker 为最短离线路径（介质=镜像 tar）。若 P3 step0 核查发现无 Docker 且不可安装，回退路线=D2'（pip venv + gunicorn + systemd，介质=wheels），P2 制备内容相应切换（见 P2 备选路线）。

**D2 元数据库：服务器本地 PostgreSQL 16 容器；数据中心 Oracle 不作 Superset 元数据库**
依据 v2 风险 3（元数据库必须 PG/MySQL，不能用 SQLite）及 Superset 官方支持范围（元数据库仅 PostgreSQL/MySQL/SQLite；Oracle 不支持，alembic 迁移在 Oracle 上无官方保障）。用户授权的数据中心 Oracle（U9"如果需要要部署数据库…单独创建表即可"）按其原话定位为**建表存储**：存放用户同步映射（`SUP_USER_DEPT`）、导出审计（`SUP_EXPORT_AUDIT`）等自定义表——这与"单独创建表即可"的授权口径一致，且规避了 Oracle 元数据库的兼容风险。**此决策为推断，请审查方重点质疑（见审查关注点）**。

**D3 用户体系：方案 A（定时同步 sys_employee→Superset 用户）为默认，方案 B（自定义 SecurityManager 直连 Oracle 认证）为可选升级**
起草时未获 SQL 执行授权，sys_employee 表结构（字段、密码哈希格式、科室关联）未核实。HIS 密码哈希大概率不可逆（无法转换为 Flask-AppBuilder 的 pbkdf2 格式），故：
- 方案 A（先行）：同步脚本把在职 sys_employee 同步为 Superset 用户 + 科室角色 + RLS 映射，初始密码按 P5 决策矩阵选定；
- 方案 B（可选）：自定义 FAB SecurityManager，登录时直连 Oracle 校验 sys_employee 的密码哈希（需逆向 HIS 哈希算法，MD5 类可行、加盐/不可逆类不可行），登录体验与 HIS 一致。
P5 step0 先核实表结构与哈希格式，再按决策矩阵定 A/B 组合。

**D4 离线介质：本地（有外网机器）构建自建镜像 + docker save**
自建镜像 `FROM apache/superset:6.1.0`，构建时装入：数据库驱动（oracledb/pymssql/mysqlclient/psycopg2-binary + Vastbase 待定驱动）与 Playwright Chromium（定时报告截图依赖）。构建在外网机器完成，内网服务器只 import 镜像 tar。Vastbase（openGauss 系）驱动候选：opengauss-sqlalchemy 方言或 PostgreSQL 兼容模式（psycopg2 + postgres dialect），以 P4 实测为准（v2 风险 1）。

**D5 版本与安全基线（v2 论断 15）**
锁定 6.1.x（介质制备时取当期最新 6.1 补丁版，起步 6.1.0）：CVE-2026-23980（SQL 注入）、CVE-2026-23982（越权改数据集）均影响 <6.0.0。强制项：SECRET_KEY 与 GUEST_TOKEN_JWT_SECRET 随机新生成（CVE-2023-27524 教训）、关闭 DEBUG、TALISMAN/CSP 配 frame-ancestors 白名单、SESSION_COOKIE_SECURE（HTTPS 就绪后）。

**D6 行数与导出参数分层（v2 论断 5/6/7）**
- 浏览/图表：ROW_LIMIT=50000、SQL_MAX_ROW=100000、TABLE_VIZ_MAX_ROW_SERVER=500000、DISPLAY_MAX_ROW=10000、DEFAULT_SQLLAB_LIMIT=1000（按 v2 论断 6 分层，P3 配置给出）；
- 导出：图表级 CSV/XLSX 为正式版能力；仪表盘整盘 xlsx 属未发布（Next）功能，不纳入验收；EXCEL_EXPORT_SYNC_MAX_ROWS=100000，超过走异步导出（Celery）→ 产物落服务器目录/取件（轨道二基础设施）。

- **断点续作机制（全计划通用）**：执行者在工作区维护 `review/round-3/执行进度.md`，每完成一步追加一行（时间/计划号/步骤号/结果/证据文件名），中断后从未完成的第一个步骤继续；每个计划的步骤均为幂等或注明重做影响。
- 长任务执行节奏：单步命令超时 10 分钟无响应即中止诊断，不暴力重试；涉及删数据的命令必须先备份。

**目标**：在能上外网的本机（或同网段跳板机）制备全套离线介质并移交内网，使 P3 在无外网服务器上完成部署（v2 风险 7：离线部署是内网第一拦路虎，实施第 0 步=离线介质制备）。
