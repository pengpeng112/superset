在 `offline-bundle/hospital_svc/` 下新建（保持单文件清晰、零额外依赖、全部基于标准库 + 镜像内置 `Flask`/`Werkzeug`/`Gunicorn`/`psycopg2`/`sqlalchemy`）：

- `auth.py`：会话身份认证与 CSRF 校验模块。
- `rbac_api.py`：RBAC 全景、预览、受控变更、审计日志接口（内部直接 import `/app/superset_home/scripts/superset_rbac_manage.py`）。
- `portal_catalog.py`：`/hospital-api/portal/catalog` 只读目录聚合模块（Batch 3 供权限中心直接读取真实看板/分类/角色映射，Batch 4 供首页与导航动态消费）。

- `wsgi.py`：Gunicorn 启动入口。

#### 2.2 身份鉴权与安全硬约束（`auth.py`）
**绝对禁止在接口中只信 `Referer` 或前端传来的 `username` 参数！** 必须按以下链路鉴权：
1. **获取真实登录态**：
   - 从 HTTP 请求头读取浏览器原始 `Cookie`（必须验证包含 `session`）。
   - 调用容器内网地址 `http://superset-web:8088/api/v1/me/`（带上原始 `Cookie`，`timeout=3.0`）。
   - 若返回状态码 `401`/`302`/非 `200` 或无 `result.username`，立即返回 **`401 Unauthorized`**，提示“登录状态已过期，请刷新页面重新登录”。
2. **以 PostgreSQL 为准核验权威角色**：
   - 拿到 `username` 后，直接查询 Superset PostgreSQL `ab_user`（必须 `active = true`）及 `ab_user_role` + `ab_role`，得出该用户精确角色列表 `roles` 与 `is_admin = ('Admin' in roles)`。
   - **权限分流**：
     - `/hospital-api/health`：仅返回服务健康布尔态与锁路径可写状态，不返回任何用户、工号、SQL 或环境变量。
     - `/hospital-api/portal/catalog`：需已登录（非匿名则返回用户可见目录，未登录返回 `401`）；返回结果按该用户在数据库中的实时权限过滤，绝不泄露无权查看的未发布/受限报表。
     - `/hospital-api/rbac/*` 与 `/hospital-api/audit/*`：**强校验 `is_admin is True`**！任何非 Admin（包括测试账号 `003158`）请求一律返回 **`403 Forbidden`**，禁止降级放行。
3. **写操作 CSRF 与同源校验**：
   - 新增只读接口 `GET /hospital-api/auth/session`：验证登录后，用服务端密钥（复用 Superset `SECRET_KEY` 环境变量经 HMAC-SHA256 派生，禁止硬编码密钥！）为当前 `username + session_hash` 签发短期时效性 Token `csrf_token`（有效期如 2 小时），连同当前用户信息与 `is_admin` 返回给前端。
   - 所有非 `GET`/`HEAD` 写请求（`/hospital-api/rbac/preview`、`/hospital-api/rbac/apply`）：
     1. 若请求带有 `Origin` 头，必须与当前 `Host` 同源；
     2. 必须携带请求头 `X-Hospital-CSRF`，经服务端 HMAC 校验与当前用户匹配且未过期，否则直接返回 `403 CSRF check failed`。

#### 2.3 API 接口清单（Batch 3 范围）
- `GET /hospital-api/health`
- `GET /hospital-api/auth/session`
- `GET /hospital-api/portal/catalog`
- `GET /hospital-api/rbac/overview`（支持 `?mode=matrix|dashboards|roles` 与筛选参数 `?q=...&dept=...&role=...&anomaly=1`）
