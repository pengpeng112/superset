## 一、为什么有这些角色

部分报表包含**患者/医师级敏感明细**（姓名、病案号、手术、处方、检验等），不能像普通报表那样全院开放。这些报表在 Superset 里通过"专项角色"门禁：**只有被加入对应角色的工号才能打开**，其余员工（含 Gamma 全员角色）访问一律 404。Admin 不受门禁限制。

专项角色命名必须以 **`报表授权_`** 开头。每日 06:00 用户同步脚本只管理 `科室_`/`role_` 开头的科室角色，`报表授权_` 前缀的角色**永远不会被同步改名、改成员或删除**（2026-11-08 已在生产容器内实跑 `--dry-run` 验证：rc=0，2382 用户全部 unchanged，日志零提及 `报表授权_`）。

## 三、如何把工号加入角色（推荐：后台界面）

用 `admin` 登录 http://10.10.8.73:8180 ，两种等价入口：

**入口 A（按人找角色，最常用）**

1. 右上角用户名 → **设置 → 用户列表**（或直接打开 `/users/list/`）。
2. 搜索框输入工号（如 `003158`）→ 找到该用户所在行 → 行末 **编辑**（铅笔图标）。
3. 在 **角色** 多选框中勾选对应 `报表授权_` 角色（可多选）→ **保存**。
4. 该员工无需重新登录，刷新页面即可看到新报表入口（左侧分类目录与首页分类计数自动出现）。

**入口 B（按角色批量加人）**

1. 右上角用户名 → **设置 → 角色列表**（或直接打开 `/roles/list/`）。
2. 搜索 `报表授权_` → 选中目标角色 → **编辑** → 在成员/用户列表中增删工号 → **保存**。

撤销授权：同样路径取消勾选并保存，立即生效。

## 四、如何用脚本授权（批量/无界面时）

在服务器（10.10.8.73，经跳板机登录）执行。**加入**工号到角色（幂等，可重复执行）：

```bash
docker exec superset-postgres psql -U superset -d superset -c "
INSERT INTO ab_user_role (id, user_id, role_id)
SELECT (SELECT coalesce(max(id),0) FROM ab_user_role)+1,
       (SELECT id FROM ab_user WHERE username='工号'),
       (SELECT id FROM ab_role WHERE name='报表授权_角色名')
WHERE NOT EXISTS (
  SELECT 1 FROM ab_user_role ur
  JOIN ab_user u ON u.id=ur.user_id
  JOIN ab_role r ON r.id=ur.role_id
  WHERE u.username='工号' AND r.name='报表授权_角色名');"
```

**移除**：

```bash
docker exec superset-postgres psql -U superset -d superset -c "
DELETE FROM ab_user_role ur
USING ab_user u, ab_role r
WHERE ur.user_id=u.id AND ur.role_id=r.id
  AND u.username='工号' AND r.name='报表授权_角色名';"
```

注意：本库 `ab_user_role.id` 无自增序列，插入时必须像上面那样显式给 `max(id)+1`；漏写 id 会直接报错（这是生产库的既有约束，不是故障）。

3. **角色成员盘点**（服务器执行）：

```bash
docker exec superset-postgres psql -U superset -d superset -c "
SELECT r.id, r.name, count(ur.user_id) AS members,
       string_agg(u.username, ',') AS 工号
FROM ab_role r
LEFT JOIN ab_user_role ur ON ur.role_id=r.id
LEFT JOIN ab_user u ON u.id=ur.user_id
WHERE r.name LIKE '报表授权%' OR r.name IN ('人工冻结')
GROUP BY r.id, r.name ORDER BY r.id;"
```
